# 歌曲 MIDI 录入操作指南

供后续 AI 和维护者录入歌曲练习数据时使用。先读完本指南，再处理曲目文件。

## 开始前：四份文件必须齐全

每首歌都必须由用户提供以下四份文件，且 MIDI 与 PDF 必须对应同一编曲版本：

1. 简单 C 调版 MIDI（`.mid` 或 `.midi`）
2. 简单 C 调版五线谱 PDF（`.pdf`）
3. 原谱版 MIDI（`.mid` 或 `.midi`）
4. 原谱版五线谱 PDF（`.pdf`）

缺任何一份、版本对应关系不清楚、文件打不开或曲名/编曲标注冲突时，**暂停录入并先向用户索取或确认**。不要用旧曲目、网上找到的版本、Audiveris 识谱结果或另一份调性的文件代替。可直接这样询问：

> 开始录入《曲名》前还需要完整的四份对应文件：简单 C 调 MIDI 和 PDF、原谱 MIDI 和 PDF。目前缺少：……请补充后我再继续。

如果用户表示歌曲只有一种调性版本，也先说明当前录入流程要求两套版本及对应 PDF，请用户补齐或明确调整产品规则后再处理。

## 数据来源和保留规则

- MIDI 是音高、起音位置、时值和声部事件的唯一录入依据。C 调版和原调版是两份独立编曲，不要自行移调、拼接或从一版推导另一版。
- PDF 是对应版本的核对和追溯材料。它能帮助检查调号、谱表、声部、段落和 MIDI/PDF 是否匹配；不要根据 PDF 人工重录音符，也不要用 PDF 改写 MIDI 事件。
- 将用户原文件原样保存在 `docs/sources/<曲目短名>-midi/`。不要覆盖、压缩替换或删除用户源文件；新增版本另存并保留清晰文件名。
- 生成的 TypeScript 数据和识别审计报告与原始 MIDI 分开保存。不要手工改写转换器生成的事件数组；需要修正转换规则时，修改并记录转换流程，再从原始 MIDI 重新生成。
- 不删除已有曲目或旧版本，除非用户明确要求删除。
- 未经用户明确要求，不添加歌词，不发布或部署。

推荐文件名示例：

统一使用“歌曲名-原谱”和“歌曲名-简单C调”作为版本名；MIDI 与 PDF 共用同一版本名，只替换扩展名。删除来源网站追加的“完整版”“五线谱下载”等冗余后缀。示例：

```text
docs/sources/<曲目短名>-midi/
  <曲名>-简单C调.mid
  <曲名>-简单C调.pdf
  <曲名>-原谱.mid
  <曲名>-原谱.pdf
  识别审计-C调.json
  识别审计-原调.json
```

## 录入步骤

### 1. 建立来源清单

记录曲名、演唱者/版本说明、四个文件的原始文件名和路径、PDF 页数，以及 MIDI/PDF 的对应关系。检查 PDF 每页页码、乐谱顺序和是否缺页；不要按文件到达顺序猜测页面顺序。保留文件哈希或其他可复核的文件标识，方便确认后续没有误换源文件。

### 2. 先检查 MIDI 结构，不先写曲目数据

检查并记录每份 MIDI 的：

- MIDI 格式、轨道数、每分钟拍数、拍号、调号、ticks per quarter（TPQ）及速度变化事件。
- 每条轨道的名称（若有）、音符事件数、音域、通道、最早起音和最后结束位置。
- 同一时刻的多音、跨手同时起音、重叠音、重复段、休止、延音/踏板相关事件，以及无法配对的 note-on/note-off。

按 MIDI 实际轨道与对应 PDF 的高音谱表/低音谱表确认右手和左手映射。轨道序号按转换脚本的 **0 起始索引**填写；不要仅凭轨道顺序、音域或通道号猜左右手。若一条轨道混有两手、左右手分在多个轨道、没有必要的元数据，或事件异常导致映射不确定，暂停并先确认处理方案。

当前 `midi_to_song_practice.py` 要求右手和左手来自两个不同的 MIDI 轨道，且 MIDI 在第 0 tick 有速度、拍号和调号元数据。它保留选中轨道的音高、起音 tick、时值 tick、轨道、通道和来源事件序号；不会自动移调、量化或删去和弦音。没有匹配起音的 note-off 会记入审计并排除在曲目音符外；没有 note-off 的起音会报错。不要把“转换成功”当成“音乐正确”。

### 3. 分别转换两种调性

每个 MIDI 各运行一次转换器。按检查结果填写轨道索引、来源文件名、输出文件和审计报告路径；以下是命令模板，尖括号内容必须替换，不能原样执行：

```bash
python3 scripts/practice-scores/midi_to_song_practice.py \
  --input 'docs/sources/<曲目短名>-midi/<C调MIDI文件名>.mid' \
  --output 'src/features/practice/song-practice/<曲目>CSource.ts' \
  --report 'docs/sources/<曲目短名>-midi/识别审计-C调.json' \
  --source-file '<C调MIDI文件名>.mid' \
  --output-symbol <合法的TypeScript常量名> \
  --treble-track <确认后的右手轨道索引> \
  --bass-track <确认后的左手轨道索引>
```

原调版同样单独运行，使用原调 MIDI、独立输出文件、独立报告和原调映射。不要共用或覆盖 C 调版输出。若转换器报错，先查明并记录原因；不要为了通过转换而默默补拍号、改速度、移动音符或丢弃事件。

### 4. 检查转换审计和 MIDI/PDF 对应关系

逐份确认审计报告中的源文件名和 SHA-256、轨道数、TPQ、速度、拍号、调号、右手/左手轨道、音符数、音域、首尾 tick、note-on/off 配对及异常。两种调性分别核对，不可只抽查其中一份。

再用 PDF 核对版本和关键锚点：开头、每个主要段落转换处、重复/跳转处、长音或休止处、结尾；比对音高走向、同时发声、手别、小节数以及明显的调号/临时记号。若 PDF 和 MIDI 不一致，保留两者并标记差异，暂停录入并向用户确认来源，不要自行选择“看起来正确”的一方。

转换器以 MIDI tick 保存精确起音和时值。界面使用的音符外观时值可能映射到有限的显示类型；检查精确 `durationBeats`、起音、小节位置和音符数量没有被显示近似值反向改写。所有同起音音符都必须保留，特别是和弦及左右手同时起音；不得去重、只取最高/最低音、合并音符或简化成单旋律。

### 5. 接入系统

- 按 `src/features/practice/song-practice/songPracticeMaterials.ts` 的类型和校验规则生成曲目数据，保留 MIDI 来源定位信息。
- C 调版和原调版使用不同的 score 数据与稳定 ID；配置默认选项按产品现有规则设置。
- 在 `songPracticeCatalog.ts` 登记曲目，并让两种调性都能被配置和练习流程选中。PDF 文件名、页数、MIDI 文件名及源哈希应写入对应来源元数据/审计材料，确保版本可追溯。
- 左手、右手、混弹只是筛选练习时展示和判定的声部；混弹须保留来源 MIDI 中同一时刻的所有音符。麦克风模式的单音简化属于练习输入策略，不得改写 MIDI 源数据。
- 如新增曲目标题、封面、简介或歌词等额外内容，只录入用户提供或明确确认的内容。

## 完成前核对

- [ ] 四份用户来源文件齐全，C 调 MIDI/PDF 与原调 MIDI/PDF 配对明确。
- [ ] 原始文件完整留档，文件名、页数、哈希和来源版本可追溯。
- [ ] 两个版本分别转换，左右手轨道映射有依据且审计中可查。
- [ ] MIDI 与系统数据的每个事件保持音高、起音、时值和同时发声关系；无静默移调、去重、量化、删音或重排。
- [ ] 速度、拍号、TPQ、小节数、首尾位置、音符数及异常都有记录。
- [ ] 通过曲目数据的结构校验；配置页和练习页能分别选择 C 调/原调及手型。
- [ ] 对照 PDF 的抽查结果和未核实范围写清楚。

## 汇报时区分验证结论

明确说明做了哪些结构校验、PDF 抽查了哪些页/小节、发现了哪些异常。若没有逐音核对或听音验证，结论应写“结构已校验，音乐准确性尚未逐音确认”，不要称为完全识别正确。说明没有运行的测试、浏览器验收或发布操作；发布必须由用户另行明确要求。
