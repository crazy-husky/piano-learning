# Spec: Mobile Staff-Page Pagination

## Objective

Make the practice staff readable on phones by showing eight notes at a time and advancing in order after the current page is completed. Keep the existing desktop rolling staff display.

## Interaction Rules

- At viewport widths up to 820px, staff-page practice renders one eight-note page at a time.
- The page advances automatically after its last note is answered correctly. There are no manual page controls or skipping.
- Show the current page and total page count at the staff's upper-right corner.
- Fixed-count practice uses the configured question count for the total. Open-ended and fixed-duration practice show pages generated by the existing adaptive queue; the total grows as the queue is refilled.
- The single-note display and desktop staff-page behavior remain unchanged.
- On mobile, hide the global navigation during a running practice session. Hide the on-screen piano when its answer mode cannot use it; show note names instead of computer-key shortcuts when the touch piano is available.
- In microphone mode, pause releases the media stream, audio context, and analysis loop. Resuming requests microphone access again and resumes timers/answers only after listening starts successfully. If reconnecting fails, practice remains paused and can be retried.

## Tech Stack

- React, TypeScript, CSS, VexFlow, Vitest.
- No new dependencies; paging and pause lifecycle add no persisted settings or session fields.

## Commands

- Test: `pnpm test`
- Type check: `pnpm exec tsc -b --pretty false`
- Production build is left to the repository pre-commit hook.

## Project Structure

- `src/features/practice/components/PracticeView.tsx`: viewport mode, queue slice, page counter, and active-session layout state.
- `src/features/practice/logic/practiceInputLifecycle.ts`: pause and resume microphone lifecycle decisions.
- `src/features/practice/components/StaffPagePrompt.tsx`: configurable notes per staff row and phone-sized rendering.
- `src/features/practice/logic/staffPageFlow.ts`: pure page slicing and count calculation.
- `src/features/practice/logic/staffPageFlow.test.ts`: paging boundary and count tests.
- `src/styles.css`: phone practice layout and touch labels.

## Code Style

Use camelCase for internal TypeScript values and keep page-count calculation in a pure helper so queue behavior can be tested independently.

```ts
const pageView = buildMobileStaffPageView({
  notes,
  currentIndex,
  firstNoteOffset,
  completedCount,
  fixedSessionCount,
});
```

## Testing Strategy

- Unit-test page boundaries, rebased queue offsets, final partial pages, and fixed versus generated totals.
- Unit-test microphone release on pause and reconnect gating on resume.
- Run the existing Vitest suite and TypeScript project check.
- Do not create persisted practice records during browser verification.

## Boundaries

- Always: keep the adaptive queue and answer scoring order; only change the visible staff slice on mobile.
- Ask first: changing page size, enabling manual navigation, changing answer/scoring semantics, or changing session history.
- Never: change desktop rolling behavior, session persistence, wire fields, or backend behavior.

## Success Criteria

- On phones, at most eight notes are visible in staff-page mode and they render at the viewport's natural width.
- The counter reflects the current sequential page and the correct known/generated total.
- Completing a page advances to the next notes without changing scheduler or score semantics.
- On desktop, the existing two-row rolling score and MIDI/keyboard behavior remain intact.
